## Why annotations cannot be generated by the project team

An author or model pretending to be two annotators is one annotation with duplicated labels. It
does not provide independence, blindness or a defensible agreement statistic. Qualified annotators
should have disaster-assessment, remote-sensing or emergency-management expertise appropriate to
the assigned cases. The benchmark custodian keeps the identity-to-token mapping outside the
repository and outside the scoring environment.

The implemented workflow enforces:

1. A custodian-created evidence packet with immutable evidence IDs and source SHA-256 values.
2. Two distinct opaque `anon:` tokens and explicit independent-work attestations.
3. A complete 0-3 judgment for every item in the shared evidence pool. Missing judgments fail.
4. No name, email, organization or user identifier in blind packets or submissions.
5. A disagreement packet generated before adjudication.
6. A third distinct blind token, a source-based rationale and a decision for every disagreement.
7. No silent modification of fields on which both annotators agreed.

### Packet and submission process

The custodian produces one packet per split. Test questions and evidence pools remain in the
custodian workspace; only the non-scorable public plan is committed here. Each packet contains:

- benchmark and assignment IDs;
- case ID, event ID, final question and metric task types;
- the closed evidence pool, evidence modalities and immutable source digest;
- no annotator identity and no answer label.

Each annotation contains expected routes and behavior, complete graded relevance, atomic claims,
claim-support evidence, visual-evidence IDs, and human-labeled regions for **every visual claim**.
Those regions are mandatory rather than optional: each visual claim must bind at least one valid
human annotation region to its supporting visual evidence. An annotation also contains SQL denotation,
injection labels, knowledge-probe status, answer denotation and exposure class where applicable.
All of these fields share one canonical disagreement/adjudication list. Compare the two independent
submissions:

```powershell
python -m scripts.benchmark_governance compare-annotations `
  --packet D:\custodian\packets\test-batch-01.json `
  --annotation D:\custodian\submissions\blind-a.json `
  --annotation D:\custodian\submissions\blind-b.json `
  --output D:\custodian\reviews\test-batch-01-iaa.json
```

After a third person reviews the source evidence and completes all decisions:

```powershell
python -m scripts.benchmark_governance finalize-adjudication `
  --packet D:\custodian\packets\test-batch-01.json `
  --annotation D:\custodian\submissions\blind-a.json `
  --annotation D:\custodian\submissions\blind-b.json `
  --adjudication D:\custodian\reviews\adjudicator.json `
  --gold-output D:\custodian\sealed\adjudicated-gold.json `
  --iaa-output D:\custodian\sealed\iaa.json
```

The generated gold records that there were two independent annotations and one adjudicator and
binds the agreement report by SHA-256. The public IAA summary retains complete case/evidence
denominators, agreement statistics, eligible/adjudicated/unresolved disagreement counts,
adjudication rate, and explicit zero-exclusion accounting while redacting labels and blind tokens.
This metadata is a protocol record, not proof that a person
was qualified; the benchmark owner must separately publish selection criteria and conflict-of-interest
disclosures without de-blinding individual labels.

Multiple split/batch outputs must never be concatenated manually. Merge them from the original
packet, two submissions and adjudication evidence; the command rejects duplicate cases and
assignments, canonicalizes case order and recomputes pooled IAA from raw labels:

```powershell
python -m scripts.benchmark_governance merge-adjudicated-batches `
  --batch D:\custodian\sealed\train-batch.json `
  --batch D:\custodian\sealed\development-batch.json `
  --batch D:\custodian\sealed\test-batch.json `
  --gold-output D:\custodian\sealed\adjudicated-gold.json `
  --iaa-output D:\custodian\sealed\pre-adjudication-iaa.json
```

## Inter-annotator agreement

The IAA report includes denominators and does not collapse all label types into one misleading
number:

| Label family | Statistic |
|---|---|
| Answer / abstain / block | observed agreement and Cohen's kappa |
| Route selection | exact set agreement, mean Jaccard and per-tool Cohen's kappa |
| Relevance 0-3 | quadratic-weighted Cohen's kappa over the complete shared pool |
| Relevant / not relevant | binary Cohen's kappa |
| Claim-support evidence | mean evidence-set Jaccard |
| Visual-support evidence | mean visual-evidence-set Jaccard |
| SQL denotation | deterministic exact agreement using the scorer's normalization |
| Knowledge-probe designation and answer denotation | observed/exact agreement |
| Exposure class | observed agreement |
| Whole case | exact agreement |

Agreement is reported before adjudication. Published results must include all values, denominators,
the number and type of exclusions, and the adjudication rate. Do not choose an arbitrary kappa
threshold after seeing test results; register acceptance criteria on train/development first.

## Frozen test-label escrow

Plaintext test labels, annotator files, private manifests and private keys belong in the external
custodian workspace. Repository ignore rules cover the documented emergency filename patterns, but
`.gitignore` is only defense in depth and cannot protect an already tracked or arbitrarily renamed
file. CI must reject any adjudicated/frozen plaintext test case discovered in a proposed commit. A
freeze operator uses a custodian-owned RSA key of at least 3072 bits. The tool:

- validates that the full gold is marked `frozen`;
- emits public train/development labels only;
- encrypts the test subset with AES-256-GCM;
- wraps its one-time AES key with RSA-OAEP-SHA256;
- emits SHA-256 commitments to plaintext gold, ciphertext and the recipient public key;
- never puts test case IDs in the public commitment.

```powershell
python -m scripts.benchmark_governance escrow-test-gold `
  --gold D:\custodian\sealed\frozen-gold.json `
  --recipient-public-key D:\offline-keys\test-escrow-public.pem `
  --public-gold-output artifacts\benchmark\public-train-development.json `
  --envelope-output artifacts\benchmark\encrypted-test-gold.json `
  --commitment-output artifacts\benchmark\test-gold-commitment.json
```

The RSA private key belongs in an offline secret manager or isolated evaluator, never a developer
machine or CI variable available to the product team. Encryption does not solve governance if the
same developers control the private key.

## Recent and private holdouts

`exposure_class` distinguishes:

- `historical_public`: public long enough that model pretraining exposure is plausible;
- `recent_public`: a 2024 or 2025 event used to reduce, not eliminate, likely pretraining exposure;
- `private_custodian`: lawful data inaccessible to system developers and model providers before
  the evaluation.

The v2 public additions contain eight newer events: Valparaiso fires, Rio Grande do Sul floods,
Zambia drought, Wayanad landslide, North India heat, Baghlan floods, the 2025 Myanmar earthquake and
the 2025 Mokwa floods. A date alone does not prove absence from model training. Every model run
therefore declares its release date and known training cutoff, or `unknown`.

Private events cannot be invented or scraped into a public repository. The independent custodian
must lawfully obtain at least three, keep their metadata and bytes access-controlled, and publish
only an opaque manifest commitment. The sealed manifest requires a unique event ID, a non-placeholder
source-lock SHA-256 and a unique 256-bit `nonce:` value for each event. The nonce prevents practical
dictionary guessing of low-entropy private metadata. Duplicate events, duplicate nonces and missing
benchmark identity fail closed:

```json
{
  "schema_version": 1,
  "benchmark_id": "crisisweave-global-disasters",
  "benchmark_version": "2.1.0-source-registry",
  "events": [{
    "event_id": "custodian-only-id",
    "exposure_class": "private_custodian",
    "source_lock_sha256": "sha256:<64 lowercase hex>",
    "commitment_nonce": "nonce:<64 random lowercase hex>"
  }]
}
```

```powershell
python -m scripts.benchmark_governance create-private-commitment `
  D:\custodian\private\private-event-manifest.json `
  --output artifacts\benchmark\private-commitment.json

python -m scripts.benchmark_governance validate-private-holdouts `
  datasets/crisisweave-disasters-v1/private_holdout_commitments.json `
  --private-manifest D:\custodian\private\private-event-manifest.json
```

Place the generated commitment object in the public registry's `commitments` array and change its
status from `blocked_pending_custodian_data` to
`committed_pending_custodian_verification`. Never place the sealed manifest or its nonces there.

The committed registry intentionally reports `release_gate_satisfied: false` and zero private
events. A public commitment file without the sealed manifest also reports false: an integer count
alone is not evidence. Only the independent release harness may reopen the manifest, recompute every
salted commitment, prove unique event IDs and match the exact private event set and source locks to
frozen gold and the corpus lock. That is an external data-governance gate, not a missing software
feature.

## Closed-book versus retrieved evidence

Exact-answer knowledge probes are run twice against the exact same model artifact, hardware,
prompt and decoding configuration:

1. `closed_book`: tools, retrieved evidence, routes and citations are forbidden by schema.
2. `retrieved`: the frozen benchmark corpus is available normally.

The gold case must be explicitly labeled `knowledge_probe`, contain a deterministic
`answer_denotation`, and carry an exposure class. The report publishes closed-book exact-answer
rate, retrieved exact-answer accuracy and retrieval lift, overall and separately for historical,
recent and private events. Closed-book correctness is evidence of parametric knowledge, not proof
of a particular training example.

```powershell
python -m scripts.benchmark_metrics score-knowledge `
  --gold D:\custodian\sealed\frozen-gold.json `
  --retrieved-run artifacts\retrieved.json `
  --retrieved-trace artifacts\retrieved.trace.json `
  --closed-book-run artifacts\closed-book.json `
  --closed-book-trace artifacts\closed-book.trace.json `
  --attestation-key-file D:\benchmark-secrets\custodian-hmac.key `
  --split test `
  --output artifacts\knowledge-attribution.json
```

## Fair six-system comparison and confidence intervals

[`experiment_matrix.template.json`](../datasets/crisisweave-disasters-v1/experiment_matrix.template.json)
freezes corpus, model bundle, hardware class, provider region, concurrency, cache policy, warm-up,
repetitions, price sheet and measurement boundary. Replace placeholder digests only after building
immutable artifacts:

```powershell
python -m scripts.benchmark_governance validate-experiment-matrix `
  path\to\frozen-experiment-matrix.json
```

The committed template intentionally fails release validation: it has `template_only: true`, zero
digests and placeholder deployment fields. Set `template_only` to `false` only in a frozen copy.
Validation also requires the exact approved configuration for every one of the six systems; an
unknown, reordered, missing or modified ablation fails.

All six run artifacts must carry the identical `experimental_control` object and identical explicit
retrieval-enabled evaluation condition. The scorer fails if one baseline changes hardware, cache,
model, corpus, region or another shared control. The only permitted difference is the already frozen
system ablation configuration.

Every score now includes per-event metrics and deterministic 95% event-cluster percentile bootstrap
intervals. Six-system comparisons additionally use a paired event bootstrap for every
candidate-minus-baseline delta. Whole events, not pages or questions, are resampled, preserving the
event-disjoint experimental unit. Publish:

- every per-event value, including failures;
- event-macro point estimate and 95% interval;
- paired baseline deltas and 95% intervals;
- bootstrap seed and sample count (default 10,000);
- sample denominators and excluded/non-applicable metrics, including gold, predicted and matched
  visual-region counts;
- non-null region visual-entailment precision, coverage and harmonic-mean metrics whenever the
  evaluated split contains visual claims; a report with visual cases but null region metrics or
  missing region denominators is rejected;
- cold and warm results separately.

The publication gate requires at least five distinct sealed-test events and five scorable samples
for every advertised metric family: retrieval, routing, SQL, claims/citations, visual regions,
abstention decisions, injection attacks, and closed-book knowledge probes. It recomputes expected
denominators from frozen gold, requires every system report to match them exactly, and rejects a
per-event or confidence-interval metric that is missing, non-finite, or inconsistent with the
reported event values. The current public source plan is intentionally not release-ready: its
sealed split has only two planned SQL cases and one planned injection case. The independent
custodian must add pre-freeze cases across existing test events; a tiny denominator cannot be
hidden behind an average or signature.

Every comparison and knowledge run must also carry complete USD cost-accounting provenance bound to
the same non-placeholder price sheet. Provider and/or compute usage must be observed, allocation
method declared, and LLM, embedding, reranking, OCR, transcription, vector/SQL stores, web search,
object storage and compute included. A request with observed latency or tokens cannot silently report
zero cost.

Do not describe overlapping intervals as a formal null-hypothesis test. With 14 test events, intervals
will be wide; this is useful uncertainty, not a defect to hide.

## Public asymmetric verification

Internal HMAC attestation remains useful between a trusted harness and scorer. It is not publicly
verifiable because releasing the HMAC key lets anyone forge a result. The custodian now signs the
exact final report bytes using an externally held Ed25519 private key:

```powershell
python -m scripts.benchmark_governance sign-report `
  --report artifacts\benchmark\final-report.json `
  --private-key D:\offline-keys\benchmark-ed25519-private.pem `
  --output artifacts\benchmark\final-report.signature.json

python -m scripts.benchmark_governance verify-report `
  --report artifacts\benchmark\final-report.json `
  --signature artifacts\benchmark\final-report.signature.json `
  --public-key artifacts\benchmark\benchmark-ed25519-public.pem
```

Third parties need only the public key. Publish its fingerprint through an organizational channel
independent of the artifact host. Signing proves byte integrity and key control; it does not prove
that the evaluator, source labels or cost accounting were honest. An independent harness must own
test decryption, execution, raw traces and signing.

## Fail-closed publication gate

Separate checks are useful during development, but no report is publishable until one command checks
them together. The independently operated release harness runs:

```powershell
python -m scripts.benchmark_governance validate-publication-release `
  --gold D:\custodian\sealed\frozen-gold.json `
  --iaa D:\custodian\sealed\pre-adjudication-iaa.json `
  --annotation-batch D:\custodian\sealed\train-batch.json `
  --annotation-batch D:\custodian\sealed\development-batch.json `
  --annotation-batch D:\custodian\sealed\test-batch.json `
  --private-holdouts D:\custodian\sealed\private-holdout-commitments.json `
  --private-manifest D:\custodian\private\private-event-manifest.json `
  --registry D:\custodian\sealed\frozen-registry.json `
  --corpus-lock D:\custodian\sealed\corpus-lock.json `
  --experiment-matrix D:\custodian\sealed\experiment-matrix.json `
  --test-envelope D:\custodian\sealed\encrypted-test-gold.json `
  --test-commitment D:\custodian\sealed\test-gold-commitment.json `
  --report D:\custodian\release\final-report.json `
  --signature D:\custodian\release\final-report.signature.json `
  --trusted-public-key D:\trust-anchors\benchmark-custodian-ed25519.pem
```

The command recomputes pooled IAA from the sealed raw annotation batches; it does not trust a supplied
average. It hashes the exact frozen-registry and corpus-lock bytes, verifies that their event IDs,
splits, exposure classes and source locks match frozen gold, requires the experiment matrix to carry
that exact corpus-lock digest, and binds both artifacts into the signed report. It also reopens each
private manifest inside the custodian boundary and proves exact private-gold correspondence.

The command rejects placeholder controls, fewer than three verified unique private events, incomplete
IAA coverage, stale escrow commitments, missing test cases, inadequate metric/event denominators,
missing baselines, reused artifact IDs, non-identical settings, fewer than 10,000 event-bootstrap
draws, absent or internally inconsistent per-event/paired intervals, silent zero cost, knowledge
probes missing historical/recent/private strata, model changes between
closed-book and retrieved runs, stale artifact digests, or an invalid signature. The signed public
report contains only a label-redacted IAA summary; disagreement values and plaintext test labels stay
with the custodian. Passing this software gate does not establish human independence by itself—the
operator, private data and trusted signing key must actually be controlled outside the product team.

## Publication stop conditions

Do not publish a benchmark score when any of these is true:

- fewer than two independent qualified annotations or no third adjudicator;
- an IAA report or disagreement rationale is missing;
- test plaintext or its private key was accessible to developers;
- fewer than three lawful private holdout events are committed;
- source bytes, questions, labels or experimental controls changed after freeze;
- one of six systems was not independently executed;
- closed-book and retrieved runs use different model artifacts;
- raw traces do not match internal HMAC attestations;
- the final report lacks a valid custodian Ed25519 signature;
- results omit per-event values, uncertainty, cost, latency or known exclusions.
